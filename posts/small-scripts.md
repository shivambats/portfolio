---
title: The small scripts I use every day
lede: Small, local tools are one of the quickest ways to make repetitive work disappear.
---

The scripts I keep are not elaborate. Most fit in a single file and do one thing well: open a pull request preview, inspect a queue, or clean a branch name.

## Prefer boring inputs and outputs

A useful script should accept obvious arguments, print readable output, and fail loudly. The goal is to remove friction, not create another private platform.

## Keep the tool close to the work

When a command belongs to a repository, put it there. When it belongs to your daily environment, give it a short name and document it in a sentence. A tool others can understand is more likely to last.
